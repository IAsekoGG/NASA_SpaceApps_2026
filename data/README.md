## Головна проблема: кадр 108_D_065 забитий радіоперешкодами (RFI)

Причину знайшла сесія «NISAR радарні дані для відстеження змін» за метаданими самих файлів (`/science/LSAR/GCOV/metadata/calibrationInformation`). Для frequencyA рівень шуму `noiseEquivalentBackscatter` над AOI дорівнює від −13.5 до −0.3 дБ (HH) і від −11.4 до +3.7 дБ (HV), а `rfiLikelihood` сягає 1e9…1e10 при документованому діапазоні [0, 1]. Для порівняння: на чистому кадрі над озером Чад шум близько −26 дБ. У продукті `noiseCorrectionApplied = False` і `rfiMitigationApplied = False`.

Незалежна перевірка за типами поверхні на стеку 80 м (медіана HH / HV, дБ):

| Дата | Забудова | Рілля | Дно водосховища |
|---|---|---|---|
| 2026-06-21 | 2.1 / 5.2 | 1.1 / 4.8 | −1.8 / 1.3 |
| 2026-08-20 | −4.9 / −9.3 | −9.2 / −10.4 | −7.7 / −10.9 |
| 2026-09-01 | −5.5 / −9.3 | −11.0 / −10.7 | −9.1 / −11.1 |
| 2026-10-19 | 2.4 / 3.9 | −5.8 / −5.0 | −0.4 / 0.7 |

Місто не повинно змінюватися на 8 дБ, а всі класи рухаються разом. Отже, зміни між датами переважно дає шум перешкод, а не поверхня, і **omnibus на frequencyA картуватиме перешкоди**.

frequencyB (5 МГц, 80 м, HH+HV) у тих самих файлах кращий (перцентилі 1/50/99 по AOI): медіана HH від −8.2 до −13.5 дБ, HV від −7.7 до −17.1 дБ. Але 21.06 і 03.07 HV ≈ HH, а 99-й перцентиль HV сягає +1.6…+3.5 дБ, тобто перешкоди ще видно. До того ж HV близький до рівня шуму.

Варіанти (рішення за командою):
- Каховка на frequencyB: дані вже на диску, проте стек ще треба зібрати з групи `frequencyB`; HV ненадійний.
- Інший трек над Каховкою (143_A_025, висхідний, 9 PROVISIONAL дат, ~18 ГБ): за метаданими шум −16 / −11 дБ, теж не чисто.
- Озеро Чад (101_A_008): шум близько −26 дБ, але повний стек займає ~66 ГБ (вільно 82 ГБ) і качатиметься ~1 год.
- Каховка як історія «чого радар не зміг побачити» плюс основний аналіз на чистому кадрі.

## Очищення від RFI (2026-11-15): `pipeline/rfi_clean.py`, `tools/eval_rfi_clean.py`, `tools/run_change_clean.py`

Вхід: кеш `cache_ts/` (обидва треки, 11 дат кожен, frequencyB, 80 м). Вихід: `analysis_rfi_clean/`.

**Модель.** Плями перешкод гладкі (30–60 км), переїжджають між датами, і межі полів крізь них видно. Отже, перешкода **додається в лінійній потужності**: s_obs = s_true + R. Стара корекція в ноутбуці віднімала фон у дБ і тому гасила контраст полів.

**Оцінка R** у блоках 1 км (`blk=12`):
1. «Темні» пікселі суші вибираються за **багатодатною** медіаною. Їхня середня потужність на дату t мінус мінімум по датах дає R. Нижній квантиль тієї самої дати не годиться: він вибирає пікселі, де шум перешкоди випадково малий, і занижував R для HV на 5–6 дБ.
2. Над дном водосховища опорою служить постійна відкрита вода: DSWx-S1 бачить воду на ≥ 80 % дат, JRC ≥ 80. Маска лише за JRC — це все колишнє водосховище, тобто рослинність. Блок води рахується лише за ≥ 10 % пікселів води: мінімум по датах середнього з 4–5 пікселів зміщений шумом донизу, і R над дном завищувався (HV −1.4 → −0.7 дБ).
3. Без обрізання хвоста: шум перешкоди має довгий хвіст угору.
4. Калібрування: HH ×1.05, HV ×1.10. Множник підібрано за водою з фолдів, які в оцінку не входили, і незалежно підтверджено контрастом полів.

**Перевірки, які в оцінку не входили** (сирі → очищені):

| | 143_A_025 | 108_D_065 |
|---|---|---|
| Середня вода HH / HV, дБ (просторові фолди) | −11.3 / −11.0 → −18.2 / −18.0 | −9.0 / −5.6 → −15.0 / −14.7 |
| Частка перешкоди, що лишилась над водою, HH / HV | −7 % / 0 % | 3 % / 4 % |
| Розкид забудови між датами HV, дБ | 2.3 → 0.4 | 3.7 → 0.5 |
| Рілля: брудна дата (R > −12 дБ) проти чистої, зсув HH / HV, дБ | +5.1 / +7.4 → 0.0 / −0.4 | +5.0 / +9.4 → +0.2 / +0.5 |
| Вода проти DSWx-S1 у коридорі русла (JRC ≥ 1 %), IoU | 0.34 → 0.51 | 0.25 → 0.45 |

Пояснення до таблиці:
- Над водою «середня» означає середнє в лінійній потужності. Медіана в дБ після віднімання зміщена: окремі пікселі шумлять навколо нуля.
- IoU по всій суші не рахуємо: DSWx-S1 сам показує «воду» на зораних полях (28.09 ~310 км² там, де води не було з 1984 року).

**Надійність.** Піксель-дата вважається надійною, якщо R ≤ 2 × сигнал (багатодатна медіана очищеної потужності). Частка надійних піксель-дат для HH: 87 % (143_A) і 80 % (108_D). Для HV: 72 % і 48 %. Тобто HV у 108_D у червні–липні по суті не відновлюється.

**Тест змін** (`03_change.py`, 143_A, 160 м, FDR 5 %), `analysis_rfi_clean/change_maps_143_A_025.png`:
- Сирі дані: змінилось 98 %, тобто тест картує плями перешкод.
- Очищені, усі 11 дат: 22 %. Частка «змін» зростає з силою перешкоди (4 % → 38 %): шум після віднімання тест не враховує.
- Очищені, серпень–листопад, лише надійні пікселі (5 170 км²): 3–33 % залежно від ENL (7.8 оцінений, 15, 30). Від сили перешкоди частка майже не залежить (r = 0.02–0.08). Зміни заповнюють цілі поля з однією датою першої зміни.

**Важливо для висновків ноутбука `nisar_kakhovka_timeseries.ipynb`.** Плями перешкод прив'язані до місцевості й корелюють між треками: оцінки R на парних датах дають r = 0.6–0.9, середні карти r ≈ 0.7. Тому збіг двох треків **на масштабі десятків км** не доводить, що зміна справжня. Зокрема, «стійка зміна, r ≈ 0.55 між треками» частково може бути спільною перешкодою. Справжність доводить узгодженість на масштабі полів.

### Тест змін із відомим фоном перешкод: `pipeline/sarstats_rfi.py`, `tools/run_change_rfi.py`

Тест отримує **сирі** інтенсивності Y і оцінку R, нічого не віднімаючи. Модель на кожну піксель-дату:

    Y_t ~ Gamma(n_t, s_t + R_t),  n_t = 1 / (1/L + eps²·R_t²/(s+R_t)²)

- `eps = 0.1` — похибка самої оцінки R, узята з калібрування водою.
- Брудні дати автоматично важать менше. Девіанси вкладених наборів дат віднімаються, тож дату зміни шукаємо так само, як у Conradsen 2016.
- Без перешкод (R = 0) тест рівно збігається з omnibus із `sarstats.py`.

Самоперевірка (`pipeline/selftest_change_rfi.py`, симуляція, усе OK):
- При H0 частка p < 0.05 становить 5.1 % без перешкод і 2.7 % там, де перешкода в 10+ разів сильніша за сигнал. Наївний тест на (Y − R) там помиляється у 99.9 % випадків.
- Потужність на зміні −3 дБ: 0.88–1.00.
- FDR 2.5 %.

Каховка, усі 11 дат, без маски, 160 м, FDR 5 % (`analysis_rfi_clean/change_rfiaware.{json,png}`). ENL спільний для обох треків — менша з просторових оцінок (29.8; для 108_D окремо виходило 45.6). Обґрунтування: режим і обробка однакові. Просторова оцінка занижена текстурою полів, часова (за сусідніми чистими датами) — завищена корельованим спеклом (60–84). Отже, 29.8 — обережний вибір. З окремим ENL 45.6 тест у 108_D позначав «змінами» 34 % дна, яке за DSWx було сухим весь сезон.

| | 143_A | 108_D |
|---|---|---|
| Змінилось | 13.7 % (1 480 км²) | 15.8 % (1 332 км²) |
| Частка змін: перешкода < 0.5× сигналу → > 10× | 15 % → 3 % | 34 % → 5 % |

Позитивного витоку немає: де перешкода сильніша, тест знаходить менше змін, тобто просто втрачає чутливість.

Перевірка двома треками на рівні пікселів 160 м:

| Клас | Змінилось у 143_A / 108_D | Зміна в обох треках: факт / очікувано | Дата першої зміни ±12 діб: факт / випадково |
|---|---|---|---|
| Рілля | 15.3 / 18.2 % | 11.2 / 2.8 % | 50 / 27 % |
| Дно водосховища | 9.5 / 11.1 % | 4.5 / 1.0 % | 37 / 28 % |
| Забудова (контроль) | 1.0 / 0.9 % | 0.1 / 0.0 % | — |

Дно проти DSWx-S1 (незалежний еталон води, ±3 доби):

| | 143_A | 108_D |
|---|---|---|
| Сухе весь сезон: змінилось | 8.5 % | 11.2 % |
| Вода весь сезон: змінилось | 11.9 % | 4.8 % |
| Перехід суша ↔ вода: змінилось | 20.5 % | 18.6 % |
| Дата зміни = перший перехід DSWx (±1 дата) | 57 % | 46 % |

**Висновок.**
- **Рілля.** Зміни справжні: в обох треках разом вони трапляються вчетверо частіше, ніж випадково, а дати збігаються вдвічі частіше за випадкові. Застереження щодо спільних плям тут не працює: тест не має позитивного витоку, а збіг попіксельний.
- **Дно.** Тест розрізняє прихід або відхід води: таких змін удвічі більше, ніж на сухому дні, а дата в половині випадків збігається з DSWx. Зміни на сухому дні (~10 %) — це рослинність або залишок перешкоди. Дати там узгоджуються між треками слабше, ніж на ріллі (37 % проти 28 % випадково). Частково це природно: вода на дні змінюється за дні, а треки розділяють 3 доби. Інтерпретувати їх обережно.

**Що не спрацювало: перешкода HH як κ · R_HV.** Перешкода HH справді пропорційна HV: r = 0.8–0.98 по блоках на більшості дат, κ = 0.14–2.6 залежно від дати. Вільний член регресії додатний восени — це справжнє зволоження HH. HV також краще узгоджується між сушею й водою, бо слабко реагує на вітер і вологу. Але R_HH = κ·R_HV дає витік у тесті змін: у 108_D «змін» стає 64 % навіть там, де перешкода в 10+ разів сильніша за сигнал, бо похибки локального κ множаться на велику перешкоду. Лишено як діагностику (`--hh-mode from-hv`, `rfi_clean.estimate_rfi_pair`).

Від параметрів висновки не залежать. За eps 0.05–0.2 зміна в обох треках трапляється в 2.9–3.8 раза частіше за випадкове (з окремими ENL). Якщо підняти ENL до 60, з'являються хибні тривоги, і цей коефіцієнт падає до 1.95. Тест свідомо обережний: `upper_ratio` ≈ 0.18.
